# QA Mart plugin demo

This is a reproducible demo of the plugin integrated into the existing framework. No live Copilot model is claimed: the checks below exercise the same hooks, MCP JSON-RPC server and Playwright files that Copilot loads.

## 1. Generate a Login test

In Copilot Chat choose **QA Test Generator**, or run `/generate-playwright-tests US-104`. The agent reads `docs/stories/US-104-sign-in.md`, `docs/team-conventions.md`, `tests/fixtures.ts`, `tests/test-data.ts`, and existing specs before it writes anything.

The generated files are:
- `pages/LoginPage.ts`
- `pages/ProductsPage.ts`
- `tests/lab/us-104-sign-in.spec.ts`

Coverage is 9 cases: valid credentials and greeting; wrong password UI + API 401; empty email and empty password with a proof that no API call is sent; locked account UI + API 423; case-insensitive email with surrounding spaces; sign-out clears cart. The values come from `tests/test-data.ts`, selectors are role/label/test id, and expected results come from US-104.

Run it:
```powershell
npx playwright test tests/lab/us-104-sign-in.spec.ts --project=chromium
npx playwright test tests/lab/us-104-sign-in.spec.ts --project=ui-v2
```

Recorded result: **18 passed** (9 on chromium, 9 on ui-v2). The spec imports `test` and `expect` from `tests/fixtures.ts`, uses `baseURL`, and passed the project typecheck and lint.

## 4. Show MCP usage

Run:
```powershell
$env:QA_PASS = 'Test@1234'
npm run plugin:mcp-smoke
Remove-Item Env:QA_PASS
```

Recorded result: **All MCP checks passed**. It starts QA Mart on port 3198 and talks to the MCP server over stdio. Representative calls:

| Tool | Input | Result |
|---|---|---|
| `auth_negative_matrix` | none | 6/6 sign-in cases match US-104: 200, 401, 423, email normalization |
| `products_get` | `{ "query": "desk lamp" }` | `{ "id": "p4", "name": "Desk Lamp", "price": 1499, "stock": 3 }` |
| `coupons_validate` | `{ "code": "FLAT100", "subtotal": 500 }` | HTTP 422; known planted bug B1, so the story-correct test must remain red |
| `orders_place` | Ravi, 2 × p2 | 201, order `QM-10001`, total ₹498 |
| `orders_security_probe` | no token; Ravi's token for Asha | actual 201 / 201, expected 401 / 403; known planted bug B3 |

`orders_reset` is destructive and advertises `destructiveHint`. Setting `QAMART_MCP_READONLY=1` disables order placement, security probe and reset. The server refuses non-local URLs unless `QAMART_MCP_ALLOW_REMOTE=1` is deliberately set.

## 5. End-to-end verification

```powershell
npm run plugin:validate
npm run plugin:test-hooks
$env:QA_PASS = 'Test@1234'
npm run plugin:mcp-smoke
Remove-Item Env:QA_PASS
npm run typecheck
npm run lint:specs
npx playwright test tests/lab/us-104-sign-in.spec.ts --project=chromium
npx playwright test tests/lab/us-104-sign-in.spec.ts --project=ui-v2
```

Expected: manifest validation and hook checks pass, MCP reports its expected planted-bug observations, repo typecheck/lint pass, the 21 chromium tests pass, and the 18 Login tests pass across both UI projects. The repository's full `npm run test:v2` also runs the legacy checkout review fixture, which intentionally fails because its `#email` selector is renamed in v2; this is pre-existing training behavior, not a regression. The untouched legacy checkout also intentionally produces 18 lint findings; it is a reviewer exercise, not silently rewritten.
